# 脚本-中文乱码

> **触发**：中文文件读出来是乱码（`缁忛獙娴佺▼`）；`ConvertFrom-Json` 报「传入的对象无效」；`Get-Content` 看中文文件出现方块或问号
> **验证**：用首选读同一文件首行，中文正常即为真。别把「文件坏了」当结论——多半是读取端编码

## 首选

```powershell
$txt = [System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes($path))
```

解析 JSON 同理：

```powershell
[System.Text.Encoding]::UTF8.GetString([System.IO.File]::ReadAllBytes($p)) | ConvertFrom-Json
```

## 被挡时

1. 用 `read` 工具读——它按 UTF-8 解析，不走控制台编码。
2. 只看内容不解析：`cmd /c type "$path"`。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| `Get-Content $p \| ConvertFrom-Json` | 先按 GBK 解成错字符，JSON 结构已坏，报「传入的对象无效（188）」 |
| `Get-Content -Encoding UTF8` | 本机是 PS 5.1，该参数行为与 7 不同；实测仍乱 |
| 怀疑下载坏了、重新下载 | 字节是好的 UTF-8；坏的是读取端 |

## 注意

- **本机 `pwsh` 实为 Windows PowerShell 5.1**（`$PSVersionTable` → 5.1.19041），不是 7。PS7 的 UTF-8 默认在这里不成立。
- 只影响读取和显示，**不影响文件本身**——`write` 工具写的一直是 UTF-8 无 BOM。

证据：2026-10-18 装机时第 1 次；2026-10-19 读 `dshmarket/package.json` 时第 2 次（复发），故成卡。
